## Notes (M3b, cand_grid)

- **Command** (tm_dev):
  `TM_REPEAT=2 TM_CANDIDATES=cand_grid TM_BUILD=/data/work/build_cand_grid TM_OUT=/data/work/eval/cand_grid ./scripts/evaluate.sh simple,cand_grid`.
  Frozen configuration = built-in defaults = `config/cand_grid.cfg`. All three systems were scored in the same
  run with the fixed scorer. `existing` is the recorded map.
- **The recording was used for tuning**, together with synthetic suite_v1, as the task allowed. It is not a
  held-out result for this candidate, and it is one mission.
- **cand_grid vs existing**:
  - better on every detection, geometry and stability row: recall 1.00 vs 0.78, mean / min IoU 0.85 / 0.75
    vs 0.63 / 0.39, centre RMSE 0.17 vs 1.36 m, neighbour spill max 0.06 vs 0.42, 0 merged entries vs 2,
    0 centre jumps and 0 height jumps vs 8 and 19;
  - 0 safety violations vs 5 (existing: a sprayed tree absorbed the hop target, the target ID vanished, and
    3 non-target changes in the descent window);
  - worse only on scan latency: 2.34 s vs 1.19 s (simple 2.39 s).
- **cand_grid vs simple**: same story. Recall +0.11, IoU +0.12, centre RMSE -0.93 m, merges 1 → 0, centre
  jumps 8 → 0, height jumps 3 → 0, latency equal.
- **Heights**: the truth heights here are a constant 4.0 m fallback, so the rows read n/a. cand_grid
  publishes 4.7-5.8 m. The measured canopy tops are 5.4-5.9 m (p90-p99 of in-canopy points,
  `geometry_check.md`). The leafy sim canopies make cell means sit below the foliage top, so cand_grid tends
  to underestimate the top here by up to about 0.7 m on some trees. **Unverified** against a real height truth.
- **The climb out of each spray hover is judged** by the scorer as part of the descent. A first version let
  neighbours grow there (7 violations), because navigation already said PLANNING while the drone was still low
  over the sprayed tree. cand_grid now keeps the descent freeze until the drone has moved 1.5 m from the hover
  point (`climbOutPolicy`, tested).
- **Cost** (x86 workstation, one core): integrate 0.47 ms / frame mean (p95 0.68), extract 0.09 ms / frame
  mean amortised (one extraction every 0.2 s). Not measured on the Orin; expect several times this.
